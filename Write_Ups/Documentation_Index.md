## How the documents connect

```text
Analytical_Goals_and_Tasks ──► Data_and_Resources ──► Data_Engineering
        │                                                   │
        ▼                                                   ▼
Analytics_Methods ◄──────────── Model_Engineering ◄─────────┘
        │                              │
        └──────────► Implementation_Design ◄──── Analytical_System_Architecture
                              │
                 Timeline_and_Milestones ◄──► Risk_Management
```

- **Goals → methods.** Each analytical task names the method section that implements it and the experiments that validate it (traceability matrix in `Analytical_Goals_and_Tasks.md` §4).
- **Methods → implementation.** Each method names its notebook phase, module and exported table. `Implementation_Design.md` describes how those pieces run, and `Analytical_System_Architecture.md` shows them as a system.
- **Implementation → plan.** Implementation activities A1–A12 map to timeline tasks T1–T14 (`Implementation_Design.md` §20). Monitoring thresholds (§19) act as risk triggers.
- **Plan ↔ risk.** The buffer, critical path and scope-cut order in the timeline are the schedule responses to risks RK-03, RK-23, RK-25 and RK-31. Every risk's mitigation names the task or mechanism that delivers it.
